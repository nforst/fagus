# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).


## [Unreleased]

### Added

- Rust: `ResourceLoader::load_many(&[&str])` answers many URLs at once, so that a loader can fetch them concurrently. A render asks with it for the resources it knows before it uses them: the linked style sheets of a document, then the first font file of each `@font-face` rule, then the images, at most `fagus::BATCH` (64) URLs at a time. The default implementation calls `load` for one after the other, so an existing loader is asked for the same URLs as before, and the PDF is the same either way. `@import`ed style sheets, later sources of a font, the sprites of inline SVG and the documents of `<iframe>`s are still asked for one by one.
- Worker protocol: a caller that sets `askMany` in `R` (with `ask`) is asked for many resources at once. The worker sends `Q` with up to 64 `urls` and reads `q` with `found` for each and the data of those found, for the style sheets, fonts and images it knows before it uses them; it keeps asking with `?` for the rest. Protocol 1 stays: an older worker ignores `askMany` and asks with `?` alone, and a worker never sends `Q` to a caller that did not ask for it. The C library takes `askMany` and ignores it, as it asks its caller nothing.

## [1.1.1] - 2026-11-25

### Changed

- The Composer plugin warns when it installs the binary for a development version of the package (a branch such as `dev-main`): a branch lists the binaries of the last release, so the binary is that release's and may not know what the branch added. The installation succeeds as before, also with `FAGUS_INSTALL_STRICT`; build the binary from the branch and set `FAGUS_BINARY` to use it.
- The FreeBSD binary, built on FreeBSD 14, is now tested on FreeBSD 15 too: CI renders documents with it there, and the release workflow runs the release's binary on FreeBSD 15 before it drafts the release.
- The workflows name their actions by commit instead of by tag, and Dependabot proposes their updates.
- A resolver (in Rust a `ResourceLoader`) is asked once for each URL in a render, whatever it answers. Before, a document with container queries, or one wider than the page that is shrunk to fit, asked again for every image each time it was laid out: up to three or four times for each image, and each time the PHP callback ran and the data crossed the pipe. A resolver that counts its calls sees fewer of them; the PDF is the same.

### Fixed

- `@supports (position: running(x))` is true, as running elements work; it was false, so a stylesheet could not lay them out only where they are supported ([#4](https://github.com/nforst/fagus/issues/4)).
- A box with `break-inside: avoid` that does not fit after a heading with `break-after: avoid` at the top of a page breaks inside, below the heading, as in Chrome: both breaks violate an `avoid`, and the later one wins. Fagus broke after the heading instead and left it alone on its page, also where the box was taller than a page and broke on the next one all the same ([#5](https://github.com/nforst/fagus/issues/5)).
- Where strict installation (`FAGUS_INSTALL_STRICT`, `extra.fagus.install-strict`) fails Composer because a copy of the package lists no binaries, the error names the way out, `FAGUS_INSTALL_STRICT=0` with a binary of your own in `FAGUS_BINARY`; it pointed to `vendor/bin/fagus-install`, which fails for the same reason.

### Documentation

- Text without a `font-family` is set in the `serif` family, which without fonts of your own is the built-in Inter and with them the first font of your font directories. That was only in a table of [fonts.md](docs/fonts.md#set-the-generic-families); getting started, the Laravel configuration, troubleshooting, the wkhtmltopdf guide and the README say it now, and the Blade example sets a `font-family`.
- A recipe for a header and footer from Blade partials, with running elements and page numbers ([laravel.md](docs/laravel.md#put-a-blade-partial-in-the-header-and-footer)).
- What the Composer plugin does for a branch is described as it is: troubleshooting, deployment and releasing said that a branch gets no binary.

## [1.1.0] - 2026-11-20

### Added

- `Pdf::inline()` and `Pdf::download()` send a PDF to the browser in one call: `Content-Type`, `Content-Disposition` (`inline` or `attachment`, with the file name and a `filename*` for names that are not ASCII), `Content-Length` and the PDF. `Document::inline()` and `Document::download()` render and send it, as `save()` renders and writes it: `Fagus::html($html)->inline('invoice.pdf')`. They throw a `FagusException` if output was already sent. Before, plain PHP needed the headers by hand and `echo $pdf->bytes()`; Laravel's `inline()` and `download()` responses stay as they are.

### Fixed

- On FreeBSD, a worker that had hardly run yet reported a peak resident memory (`maxRss`) of 0; it now leaves the size out until the system knows it, as on platforms without one.

## [1.0.0] - 2026-11-20

The first stable release: from now on, only a major release changes the API ([stability](docs/stability.md)). [UPGRADING.md](UPGRADING.md) lists what an update from 0.x can need.

### Added

- Footnotes (CSS Generated Content for Paged Media 3), as WeasyPrint and Prince print them; Chrome has none. `float: footnote` moves an element into the footnote area at the bottom of the page its call is on, which `@page { @footnote { … } }` styles (margins, borders, padding, background, `max-height`; a top margin of `1em` by default) and which takes its room from the content of the page. `::footnote-call` (a superscript `counter(footnote)` by default) stays in the text, `::footnote-marker` (`counter(footnote) ". "`) starts the footnote. The `footnote` counter counts through the document, or from each page that resets it with `@page { counter-reset: footnote }`. A footnote that does not fit starts below the line of its call and goes on at the top of the next page's footnote area, or goes there whole where not even `orphans` lines of it fit (`footnote-policy: auto`; the text after the call stays where it fits); `line` and `block` take the line or the paragraph of its call with it. `footnote-display: inline` and `compact` set footnotes side by side, on lines that break across pages too. The call is a link to its footnote, the marker one back to the call. Tagged PDFs have each footnote as a `Note` with its marker as a label, and the call and the marker as `Link`s with their annotations. `float-reference` takes `inline`, `region` and `page`, which all put footnotes into the footnote area of the page, and `column`, which puts a footnote called in a column of a multi-column layout into a footnote area at the bottom of that column, as Prince does: balanced columns are balanced with their footnotes, and a footnote that does not fit takes the line of its call to the next column. Before, `float: footnote` was ignored with a `css.invalid-value` diagnostic, and `footnote-display`, `footnote-policy` and `float-reference` were unknown properties.
- `-fagus-page-height: fit-content` in `@page`, a Fagus extension ([ADR 6](docs/adr/0006-pages-that-grow-with-their-content.md)): the page grows with its content, one page as tall as the content and the margins, for receipt printers with 80mm rolls. The height of `size` is the least the page is tall and what viewport units refer to; the page is at most 14,400pt tall, the largest page a PDF holds, and rounded up to whole points. Margin boxes, page counters, backgrounds and fixed boxes follow the grown page. `@supports (-fagus-page-height: fit-content)` is true, other values are ignored with a `css.invalid-value` diagnostic, and the diagnostic for `size: 80mm auto` points to the extension. Rendering again and again to find the height at which `pages()` is 1 is no longer needed.
- `@page :nth(An+B)` and `:nth(An+B of name)` select pages by their number in the document or in each page group of a name, the pages of an element with a `page` name and a forced break before it (CSS Generated Content for Paged Media 3): `@page :nth(1 of chapter)` styles the first page of every chapter. `@page :first` stays the first page of the document.
- `hanging-punctuation` (CSS Text 3), which Chrome does not support and Safari does: `first` and `last` let an opening quote or bracket at the start of a block's first line and a closing one at the end of its last line hang outside the text's edge, `force-end` lets a stop or comma at the end of any line hang, `allow-end` only where it does not fit otherwise. Hanging marks take no room for line breaking, alignment, justification and the widths of boxes that size to their content, and do not make the page shrink to fit. `@supports (hanging-punctuation: first)` is true now; an invalid value is ignored with a `css.invalid-value` diagnostic.
- `-fagus-layer: "Name"` puts what an element paints on a layer of the PDF (an optional content group), which a reader shows and hides in the viewer; `-fagus-layer: "Name" screen` shows it on screen only, so that a printout leaves it out, and `-fagus-layer: "Name" print` in print only. Elements with the same name share a layer, and tagged content on a layer stays in the structure. PDF/A and PDF/UA allow layers but not ones that depend on printing: there they show in both media, with a `pdf.layer-shown` warning; PDF/A-1 has no layers, the content is printed without them with a `pdf.layers-unsupported` warning. `@supports (-fagus-layer: none)` is true. The reasons are in [ADR 7](docs/adr/0007-layers-for-screen-and-print.md).
- BMP images, read as Chrome reads them: 1, 2, 4 and 8 bits per pixel with a color table, 16, 24 and 32 bits with or without bit fields, RLE8 and RLE4, bottom-up and top-down, OS/2 and Windows headers up to `BITMAPV5HEADER`. A 32-bit image has alpha only where a mask says which bits are alpha, as in Chrome.
- TIFF images, which Chrome does not show and Safari does, for scanned documents and receipts: the first image of the file, gray (1 to 16 bits, black or white as zero), RGB and RGBA, CMYK and YCbCr, uncompressed or compressed with LZW, Deflate, PackBits, CCITT Group 4 (fax) or JPEG, turned as its orientation tag says. `<picture>` and `image-set()` take TIFF sources, as Safari does.
- BMP and TIFF images also show in SVG (`<image>`), in masks, border images and backgrounds, and with filters.
- PDF files as images, as Safari and Prince show them (Chrome shows none), for letterheads designed elsewhere as page templates, as mPDF's `SetDocTemplate()` uses them (#1): `@page { margin: 25mm; background: url(letterhead.pdf) -25mm -25mm no-repeat }`. A page of the file, the first or the one the URL's fragment names (`letterhead.pdf#page=2`, RFC 8118), is drawn as a Form XObject with its text, vector graphics, fonts and images as they are, once in the PDF however many pages show it; it is as large as its crop box, turned as `/Rotate` says (a point is 4/3 CSS pixels). `@page :first` and `@page :nth(2n)` go through the pages of a template in turn. PDF images show in `<img>`, `<picture>` (`type="application/pdf"`), `<object>` and `<embed>` (also with `type="application/pdf"`), backgrounds, border images, list markers, `content` and `image-set()`; their links, annotations and tags are not taken over, and in tagged PDF a template is an artifact. A file that needs a password (`image.unsupported`), PDF 2.0 (`image.unsupported`), a page the file does not have (`image.broken`) and files of more than 128 MiB or with more than 128 MiB of page content (`image.too-large`) are left out with a diagnostic; PDF/A and PDF/UA refuse PDF images, whose content cannot be checked. The files are read with hayro-syntax (through krilla's `pdf` feature); a new fuzz target `pdf` covers it.
- AVIF images, as Chrome shows them: 8, 10 and 12 bits, 4:2:0, 4:2:2, 4:4:4 and monochrome, with an alpha channel (also premultiplied), grids, and the first frame of an animation; turned as `irot` and `imir` say (which `image-orientation: none` keeps, as in Chrome) and cropped by a clean aperture at the top left corner. An ICC profile goes into the PDF with the pixels; colors of other code points (Display P3, BT.2020, HDR with PQ or HLG …) are converted to sRGB as Chrome draws them. `<picture>` and `image-set()` take AVIF sources now instead of skipping them, and AVIF images show wherever other images do, in SVG and with filters too. The AV1 pictures are decoded by rav1d, the Rust port of dav1d, without assembly, so the build needs no C compiler and the pixels are the same on every platform; the binary grows by about 1.4 MB. A new fuzz target `avif` covers the container and the decoder.
- Fill-in forms: with `forms()` in PHP and Laravel, `Document::forms(true)` in Rust, `--forms` on the command line or `forms` in the worker protocol, form controls become the fields of an interactive form (AcroForm) that readers fill in in a PDF viewer. Text fields (`text`, `email`, `number`, `tel`, `date`, `password` and the other types that take text), text areas, checkboxes, radio buttons (one field for each `name`), drop-down lists and list boxes (`<select multiple>` and `<select size>` above 1, with every `selected` option chosen) get their `name` (periods make a tree of fields), their value, `checked` or `selected` state, and `readonly`, `disabled`, `required` and `maxlength`. Buttons that submit a `<form>` (`<button>`, `<input type=submit>`) become push buttons that send its fields to the `action` (or `formaction`, which must be an absolute `http`, `https` or `mailto` URL) with its `method` in the HTML form format, and reset buttons reset its fields; both are left as printed with PDF/A, which forbids fields that act. Each field lies where its control is laid out and shows what the control shows in an appearance of its own, so the PDF looks the same in every viewer and as without forms, and works with PDF/A-1b to PDF/A-4 and PDF/UA-1, where each field is a `Form` element of the structure with its widget. A control in a transformed box (`transform`, `rotate`, `scale`) gets the rectangle around the box as drawn as its widget, with its appearance turned as the box is; fields turned by a multiple of 90°, and fields on pages turned with `page-orientation`, tell viewers to draw a changed value turned too (`/MK /R`), while other angles show their value as printed until a reader changes it. Off by default, so that controls print as they look, as in Chrome; controls in an `inert` element stay so. The worker answers `forms` (as it answers `encrypted` and now `signed`), so that the PHP package refuses a PDF from an older binary that left the fields or the signature out.
- Password protection: PDFs encrypted with AES-256 as PDF 2.0 defines it (the standard security handler, revision 6), with a user password to open the file, an owner password that lifts restrictions, and permissions for printing, low-quality printing, changing, copying, annotating, filling in forms and assembling pages. `encrypt(userPassword: …, ownerPassword: …, permissions: [Permission::Print, …])` in PHP and Laravel with the new enum `Permission`, `Document::encrypt(Encryption::new()…)` in Rust, `encryption` in the worker protocol (with `encrypted` in its answer, so that the PHP package refuses a PDF from an older binary that left the passwords out), and `--user-password`, `--owner-password`, `--permissions` on the command line, the passwords also from files (`--user-password-file`, `--owner-password-file`) or the environment (`FAGUS_USER_PASSWORD`, `FAGUS_OWNER_PASSWORD`). Every string and stream is encrypted, including the metadata and attachments. The keys and salts are random, so an encrypted PDF is not byte-reproducible. PDF/A forbids encryption: a password with PDF/A or Factur-X is refused. PDF/UA allows it, since the extraction for accessibility (bit 10 of `P`) is always allowed, whatever the permissions: `accessible()` and `encrypt()` go together. Passwords are prepared with SASLprep (RFC 4013), as PDF 2.0 requires, so that `ä` typed composed or decomposed, a no-break space and a space, or `ﬁ` and `fi` open the same file; a password with a character SASLprep forbids (a control or private-use character, a direction mark, right-to-left letters mixed with left-to-right ones) is refused without being shown.
- Digital signatures (PAdES baseline B-B, and B-T with a timestamp): `->sign(Signature::fromPkcs12($path, $password))` in PHP and Laravel, `Document::sign(Signature::pkcs12(…))` in Rust, `--sign-p12` on the command line (password from `FAGUS_SIGN_PASSWORD` or `--sign-password-file`) and `signature` in the worker protocol. Keys are RSA or ECDSA P-256 from a PKCS#12 file, or held outside (HSM, key management service) and used through a callback that signs a digest: `Signature::withSigner(certificates: […], signer: fn (string $digest, string $algorithm): string)` in PHP, the trait `Signer` in Rust, the messages `S` and `s` in the protocol. A callback timestamps the signature with an RFC 3161 authority (`timestamp()`, the trait `Timestamper`, the messages `T` and `t`); Fagus itself still goes to no network. The signature is a field added to the finished PDF as an incremental update, invisible unless it is placed (below), with CMS signed data over the whole file (SHA-256, `signing-certificate-v2`, the time of signing as `/M`), and works with PDF/A and tagged PDF. Reason, location, contact and name are optional; the time of signing is the creation date unless given, and RSA and ECDSA (RFC 6979) signatures are deterministic, so a signed file is reproducible. `PdfError` has a new variant `Sign`. An encrypted PDF can be signed: the signature's incremental update is encrypted with the file key, except the signature value (ISO 32000-2, §7.6.2). `Signature::fromPkcs12Data($data, $password)` in PHP takes the bytes of a PKCS#12 file. Certification signatures (DocMDP): `certify(Certification::FillForms)` (`NoChanges`, `FillForms`, `Annotate`) in PHP and Rust, `--sign-certify` and the protocol's `certify`. Visible signatures: `visibleOn('id')` places the signature field in the box of an element, whose content becomes its appearance, and `visibleAt(page, x, y, width, height)` in an area of a page (`visible_on`, `visible_at` in Rust, `--sign-element`, the protocol's `element` and `area`); they work with tagged PDF, PDF/UA, PDF/A and encryption. Long-term signatures: `revocation()` adds the certificates and their OCSP responses or CRLs, which a callback gets for each certificate (`Fagus\RevocationRequest` with the OCSP request and the URLs the certificate names; the trait `Revocation` in Rust; the messages `V` and `v` in the protocol), in the document security store (PAdES B-LT), and `archiveTimestamp()` adds a document timestamp after it (B-LTA). pyHanko validates such files.
- PDF/A-1b and PDF/A-4, 4e and 4f: `Conformance::PdfA1b`, `PdfA4`, `PdfA4e` and `PdfA4f` in Rust and PHP, `'1b'`, `'4'`, `'4e'` and `'4f'` for `pdfA()`, `--pdfa` and the worker's `conformance`. PDF/A-1b is written as PDF 1.4 with a cross-reference table and without object streams; it forbids transparency, so content that does not show is clipped away, `isolation` is left out and images whose pixels are all opaque lose their alpha channel, and a document with other transparency (`opacity`, translucent colors, transparent images, blend modes, masks, shadows) is refused with a message that says what is transparent and on which page it first appears. PDF/A-4 is written as PDF 2.0, with its metadata in XMP alone; PDF/A-4f takes attachments. A Factur-X invoice raises PDF/A-1b to PDF/A-3b and refuses PDF/A-4, which Factur-X 1.07 does not allow; `accessible()` (PDF/UA-1, on PDF 1.7) goes with neither PDF/A-1b nor PDF/A-4. `tools/validate.sh` checks the new levels with veraPDF.
- Where elements ended up after rendering: with `reportLayout()` in PHP and Laravel, `$pdf->layout()` returns a `Fagus\Layout` with the pages and, for every element with an `id`, its boxes (page, position and size in PDF points from the top left of the page, one per page and per line) and, for tables, which rows went on which page (`Layout\Element`, `Layout\Box`, `Layout\Row`, `Layout\Section`, `Layout\Page`). It takes the place of the scripts people run after layout elsewhere: render, read where things landed, adjust, render again. Without `reportLayout()`, `layout()` throws a `FagusException` and rendering is as fast as before. In Rust, `Document::report_layout(true)` fills the new field `Output::layout` (`Layout`, `LayoutPage`, `LayoutElement`, `LayoutBox`, `LayoutRow`, `RowSection`); on the command line, `--layout-json <FILE>` writes it as JSON; in the worker protocol, `layout: true` in `R` adds a `layout` to the header of `P`.
- A `fagus` driver for spatie/laravel-pdf 2, registered when that package is installed: `Pdf::view(...)->driver('fagus')`, or `LARAVEL_PDF_DRIVER=fagus` for every PDF. The format, paper size, orientation and margins become an `@page` rule that wins over the document's, the header and footer views become running elements in the page margins with `@pageNumber` and `@totalPages`, and documents start with the base directory, root and tagging of `config/fagus.php`. `scale()` and `pageRanges()` throw a `CouldNotGeneratePdf`.
- The PHP engine can replace its worker with a new one after a number of documents or when the worker has grown beyond a memory limit: `maxDocuments` and `maxMemory` (megabytes) of `Engine`, `max_documents` and `max_memory` in `config/fagus.php` (`FAGUS_MAX_DOCUMENTS`, `FAGUS_MAX_MEMORY`). A long-running worker keeps memory its allocator holds after large documents; a new one starts small, at the cost of starting a process. Off by default.
- `fagus worker` reports its resident memory with every answer to a document: `rss` (now, on Linux) and `maxRss` (its peak, on Linux and macOS), in bytes.
- On Linux, `fagus render` and `fagus worker` render in a sandbox: once the input and the fonts are read, Landlock lets the process read only the files of the document's root (`render`) or of `--allow-read` (`worker`, every file without it) and the system fonts, and write, create and execute none, and a seccomp filter refuses networking, starting programs and processes, `ptrace` and kernel interfaces that rendering never uses. It is a best effort: what the kernel does not support is left out (`FAGUS_LOG=debug` says what is in force). `--no-sandbox` turns it off, in PHP `new Engine(sandbox: false)`, in Laravel `sandbox` in `config/fagus.php` (`FAGUS_SANDBOX`). The worker's `H` says how much of it is in force (`sandbox`), as does `Engine::sandbox()`. There is no sandbox on macOS and Windows (docs/cli.md#sandbox).
- `--memory-limit <MIB>` and `--cpu-limit <SECONDS>` for `fagus render` and `fagus worker` limit the address space and the processor time of the process on Linux.
- A memory budget and a time limit for each document, which bound it as a whole where the limits before bounded each part: a document that needs more ends with an error and the diagnostic `limit.memory` or `limit.time`, without a crash, and the worker goes on with the next one. The budget (2 GiB by default) counts an estimate of what the large parts hold: the document tree, computed styles, layout boxes and fragments, table cells with the rows they span, display lists, decoded images (four bytes a pixel), pixels rasterized for filters, shadows and masks, `@font-face` fonts and the bytes of resources. The time limit (none by default) is wall-clock time, checked for each element, box, line, page, image and resource. `Limits` with `Engine::set_limits` and `Document::limits` in Rust (`Error::MemoryBudget`, `Error::TimeLimit`), `--memory-budget <MIB>` and `--time-limit <SECONDS>` for `fagus render` and `fagus worker`, `memoryBudget` and `timeLimit` in the worker protocol, `memoryBudget` and `timeLimit` of the PHP `Engine` and `memory_budget` and `time_limit` in `config/fagus.php` (`FAGUS_MEMORY_BUDGET`, `FAGUS_TIME_LIMIT`). The PHP engine passes a time limit a tenth less than its `timeout` unless `timeLimit` is set, so that a document that takes too long ends with a `RenderException` and the worker stays. Neither limit changes the PDF of a document that stays within it.
- `Engine::system_font_directories()` in Rust: the directories of the system fonts, which a sandbox around the engine must let it read.
- Releases have a CycloneDX SBOM of each binary (`fagus-<target>.cdx.json`) and GitHub artifact attestations of the binaries, their SBOMs and `SHA256SUMS`, which `gh attestation verify` checks (SECURITY.md). `tools/pin-binaries.php` checks the sums and attestations of the binaries before it pins them.
- SECURITY.md describes the threat model, the limits and the risks that remain.
- A compatibility page in the documentation (`docs/compatibility.md`) with the pass rates of the reftests of web-platform-tests by directory, which `tools/wpt/run.sh` runs at a pinned commit with Fagus rendering both test and reference (nightly in CI, against the expectations in `tools/wpt/expectations.txt`; the manual tests of named strings in `css-gcpm` against references of our own in `tools/wpt/references`), and a release gate that prints the corpus with Chrome for Testing 157 on Linux and requires 95 % of the documents to match Fagus' within a tolerance (`tools/chrome-corpus.sh`).
- `tools/validate.sh` also renders the corpus as encrypted PDF/UA-1, without and with a user password, and checks both with veraPDF (the latter decrypted by qpdf, after it shows that the extraction for accessibility is allowed).
- Binaries for FreeBSD on x64 (`x86_64-unknown-freebsd`), built and tested on FreeBSD 14, which the installer picks on FreeBSD (#2). They print the same PDF as the other platforms. There is no sandbox on FreeBSD; the worker reports its peak memory (`maxRss`) as on macOS, and with system fonts Fagus reads the directories that fontconfig's configuration in `/usr/local/etc/fonts` lists.
- `FAGUS_INSTALL_STRICT=1`, or `"extra": {"fagus": {"install-strict": true}}` in the root `composer.json`, makes `composer install` and `composer update` fail with the reason when the binary cannot be installed, instead of printing a warning (#2). The default is unchanged.
- An experimental C library, `crates/fagus-ffi` ([C library](docs/ffi.md), [ADR 8](docs/adr/0008-c-library-experimental.md)), for calling Fagus in-process through FFI, from PHP or any language that calls C (#3): a shared and a static library with the header `fagus.h`. It takes the render requests of the worker protocol (the JSON header of `R` and its data blocks) and answers with the header of `P` or `E` and the PDF, and asks the caller nothing: `ask`, and signatures with `certificates`, `timestamp` or `revocation`, are answered with an error. Each release has it as `fagus-ffi-<target>.tar.gz` for Linux (x64 and arm64, glibc), macOS and Windows, with the header, an SBOM and attestations; `cargo build --release -p fagus-ffi` builds it elsewhere. The PHP package does not use it and keeps its worker, which renders as fast once it runs; the library saves the start of the worker, about 5 ms in each PHP-FPM request that renders. It is not covered by the stability promise (`fagus_abi()` returns 0). `tools/ffi.php` calls it from PHP.

### Changed

- Scroll bars: `scrollbar-gutter` (CSS Overflow 4) is supported as Chrome on Linux prints it: `stable` keeps the room of a vertical scroll bar beside the content of a box with `overflow` `hidden`, `auto` or `scroll`, empty where it has no bar, and `stable both-edges` on both sides; before, it was ignored. A scroll container with `resize` other than `none` has Chrome's resize handle in its bottom corner, over its content where it has no scroll bars and in the corner of its bars where it has them (a single bar now ends before that corner); before, only text areas had one. The handle's lines are hairlines at 45 % alpha, as in Chrome's PDF, instead of lines of 1px at 60 %, which changes how every text area is printed a little.
- With system fonts, a character that the families of bold or italic text lack is set in the regular face of the installed font it falls back to (DejaVu Sans, Noto Sans Thai …), made bold or slanted, as fontconfig answers Chrome on Linux, which asks it without the weight and style of the text. Before, Fagus took the bold or italic face of that font (DejaVu Sans Bold). The characters of Japanese, Korean, Chinese and Hindi text (by `lang`) still take the face of their weight and style, as in Chrome.
- Scroll bars are printed, as Chrome on Linux prints them: a box with `overflow: scroll`, and one with `overflow: auto` whose content overflows it (a long line of code in a `pre`, a wide table in a `.table-responsive` wrapper, a `<textarea>` with more lines than rows), gets a classic scroll bar 15px thick between its border and its padding, with arrow buttons and, where the content overflows, a thumb at its start. The bar takes room from the box's content (or adds to an auto height), so the content beside and below it moves. Before, Fagus printed none and kept no room for them, as Chrome on macOS, whose overlay scroll bars print nothing, except a fixed 16px beside every `<textarea>`, which is now there only where the text area has a scroll bar. `scrollbar-width` (`auto`, `thin` for 10px, `none`) and `scrollbar-color` are supported now; to print no scroll bars and keep no room for them, give the scrolling boxes `scrollbar-width: none` (for example `@media print { pre { scrollbar-width: none } }`), or `overflow: hidden`. A document with an overflowing `overflow: auto` box is laid out again with its scroll bars, which takes longer.
- Text fields are as wide as in Chrome on Linux: `size` (20 by default) characters of the average width of the font's OS/2 table, rounded up where it rounds up, plus the width of the box around all its glyphs less one character (the `head` table); Fagus took the width of an "x" and the ascent, as Chrome on macOS. A default text field in Arial (Liberation Sans) at 13.33px is now 177px wide instead of 145px. The spin button of a number field and the room for the arrow of a `<select>` are 15px wide, as on Linux, not 11px.
- The x-height and cap height of a font are those Chrome on Linux takes, for `ex`, `cap`, `vertical-align: middle`, `font-size-adjust`, `text-box-edge` and MathML: the OS/2 table's where it has them (it was the top of the "x", as on macOS); for a TrueType font without them (OS/2 version 1, such as DejaVu) the top of its "x" and "H" as FreeType's hinting fits them to the pixel grid, in whole pixels from 8px on. `14ex` in DejaVu Sans Mono at 14px is now 112px (8px an `ex`), as in Chrome, not 107.2px.
- Text is as wide as Chrome on Linux sets it: a glyph's advance is scaled as FreeType scales it at the font size Skia sets, cut to 1/64 pixel, where it was Core Text's advance at the exact size, as on macOS. At 11pt (14.67px, set as 14.66px) a line is 0.07 % narrower, at 10pt 0.04 %, at whole sizes in 1/64 pixel (12pt, 16px) as wide as before; a word that just did not fit at the end of a line may fit now, as in Chrome: diploma-fullbleed of the corpus now ends a line with "com‐" as Chrome on Linux does.
- MathML measures the ink of glyphs as Chrome on Linux does: the outline hinted as FreeType hints it with fontconfig's `hintslight` (CFF outlines by their own hints, TrueType outlines by the auto-hinter from 8px on), its box rounded out to whole pixels. It was the outline's box as Core Text gives it on macOS. Scripts, limits, fractions, radicals and stretched operators move by up to 4px: an inline sum of 11pt in STIX Two Math is 12px high above its baseline instead of 11.47px, and its upper limit 9px above the baseline instead of 8px. The four MathML documents of the corpus now match Chrome on Linux.
- The window Chrome loads and prints a document in is that of Chrome on Linux, 780 × 380 pixels, which Fagus' reference is (it was macOS's, 756 × 469): `background-attachment: fixed` is sized and placed in it, sticky boxes in the flow stick in it, and `sizes`, `vw` in `sizes` and the `media` of `<picture>` sources are evaluated on it. A centered fixed background moves, a box with `position: sticky; bottom: …` sticks 89 pixels higher, and `srcset` may pick another candidate where `sizes` depends on the window's width.
- Long documents take less memory while their PDF is written: the DOM and the computed styles go with the laid-out pages before the PDF is written, and the display list of each page goes once the page is written (in documents without images). For the 100-page benchmark invoice, the footprint while the PDF is written falls from 100 to 83 MB on macOS; the whole render, which now peaks while the pages are laid out, from 97 to 96 MB (110 to 102 MB with modern CSS). The PDFs are the same. `bench/README.md` says where the rest of the memory goes.
- Long documents take about half the memory: elements whose computed values are the same (the rows of a table, their cells, the items of a list) share one copy of them instead of 2.7 KB each. For the 100-page benchmark invoice, the peak footprint of a render on macOS falls from 96 to 51 MB (102 to 60 MB with modern CSS), below the performance budget of 64 MB, and the render takes 4 to 15% less processor time. The PDFs are the same.
- On Linux with glibc, `fagus worker` hands the memory its allocator keeps free back to the system after each document (`malloc_trim`): after the 100-page invoice it keeps about 20 MB instead of 63 to 125 MB, at no measurable cost. `FAGUS_MALLOC_TRIM=0` in its environment turns it off. This is the one call of `unsafe` code in Fagus; the engine's crates still forbid it.
- The PHP engine compares the version of the binary with the release of the package. A binary of another release that speaks the same protocol still renders, but it ignores options newer than itself without a word, so the engine now warns about it, once per process and binary: through the new `onWarning` argument of `Engine`, else to PHP's error log; the Laravel integration writes the warning to Laravel's log. A binary of another protocol is refused as before, with a message that now names the binary, both versions and how to install the binary of the package's release. `docs/protocol.md` lists the fields that came after protocol 1 began, with their release.
- `fagus render` opens its output file before it renders: an output that cannot be written fails before the work. A file it created is removed again when rendering fails; one that was there keeps its content, as before.
- A `content` value that combines `element()` with other values, such as `element(a) element(b)` or `element(title) " – " counter(page)`, is invalid, as CSS Generated Content for Paged Media 3 specifies: the declaration is ignored with a `css.invalid-value` diagnostic. Before, the margin box showed the first running element only.
- A `size` in `@page` that Chrome does not take, such as `80mm auto`, `A6` or three lengths, is still ignored, but now with a `css.invalid-value` diagnostic at its rule that says what is wrong: that a page's height cannot follow its content and both lengths are needed, or the size in millimetres of a paper size Chrome does not know (`105mm 148mm` for A6). Before, the page kept the size that applied before without a warning.
- Rust: the public enums and the structs with public fields of the crate `fagus` that may grow are `#[non_exhaustive]`, so that a minor release after 1.0 can add a variant or a field: `Error`, `PdfError`, `FontError`, `Conformance`, `Relationship`, `FacturXProfile`, `Algorithm`, `Output`, `Timings`, `Failure`, `Diagnostic`, `Attachment` and `Date` (`Permission` and the layout types were already). Build them with the new constructors instead of struct literals: `Attachment::new(name, mime_type, data)` with `description(…)` and `relationship(…)` (the relationship is `Unspecified` unless given), `Date::new(year, month, day, hour, minute, second)` (a `const fn`), `Diagnostic::new(severity, code, message, source)` with `at(line, column)`, `Output::default()` (new) and `Timings::default()`; a `match` over one of the enums needs a `_` arm. `Severity` stays exhaustive. See `UPGRADING.md`.
- The public API and its deprecations are settled ([ADR 5](docs/adr/0005-public-api-and-deprecations.md) is accepted, `docs/stability.md`): security fixes go into the latest minor release, and after a new major release into the last minor release of the previous major for six more months (`SECURITY.md`); the crate stays a Git dependency, not on crates.io; where the installer puts the binary is not API; PHP deprecations are reported once per call site; breaking changes planned for the next major release are collected in `UPGRADING.md` under *Next major*.

### Fixed

- Text as wide as Chrome on Linux sets it, everywhere: left-to-right words in a right-to-left line start where its alignment puts them, the spaces that hang before them as wide as Chrome's item of them; the room that rounding an item of text up to 1/64 pixel adds lies at its right end also right to left (not between its words); balanced lines are measured with that rounding as they are laid out, so that inline boxes no longer push a word onto a line of its own; an outside list marker ends where its box (its text rounded up) ends; and a direction mark or another character the shaper sets without advance takes none.
- Grid tracks share what a spanning item needs as Chrome shares it, each what is left divided by the tracks left: five `auto` tracks under an item 100.015625px wide add up to that, where they lost up to four 1/64 pixels, which made text in them wrap.
- Scroll bars as Chrome on Linux prints them in more boxes: a table cell with `overflow: auto` or `scroll` gets them, an image does not (`overflow` only clips it); a bar takes its room from `min-width` and `max-width` (`min-height` and `max-height`) as from `width` (`height`), so that a box with `max-width: 60px` stays 60px wide; content that `overflow: clip` clips along one axis still overflows along the other, what a box with layout containment holds overflows it only as ink, as CSS Containment 2 has it, and a relatively positioned child adds the end padding where flow put it, not where it was moved to.
- Scroll bars: absolutely positioned boxes in a scroll container are placed inside its scroll bars and `scrollbar-gutter`, not over them; a resize handle is drawn over the boxes the container holds that are painted as layers (`will-change: transform`, positioned children), as Chrome draws it, and not on `::before` and `::after`; spaces that hang at the end of a line no longer make a box with `overflow: auto` scroll.
- Fill-in forms: a field lies only where its control shows. A control that reaches out of the page area or out of a box with `overflow` other than `visible` was a field over all of its box, which a viewer drew uncut over the margin or the content around; now its field covers the part that shows, with its appearance cut to that part where it was printed, and a control that is cut off entirely is no field and stays as it is printed ([docs](docs/pdf.md#fields-that-are-cut-off)).
- An image whose URL has a fragment (`sprite.svg#icon`) loads from the data handed over with `resource()` under its URL without the fragment, and from a resolver or loader that knows only that URL, which is asked again without the fragment; the file is loaded once for all its fragments and the URL without one. Before, such images reported `resource.not-loaded` unless they were files.
- Repeating linear gradients of solid bands (hard stops only, such as the bars of a barcode drawn with `repeating-linear-gradient`) are repeated in the PDF by a shading with a PostScript function, as Chrome repeats them, instead of an axial shading of all their periods: viewers such as Poppler draw an axial shading from a table of colors a pixel apart, which blurred bands a pixel or two wide into gray. PDF/A, which forbids PostScript, keeps the axial shading. form-tax-comb-fields of the corpus now matches Chrome on Linux.
- A resource that a document loads under many URLs (`logo.png?1`, `logo.png?2`, …, or the same bytes under several names) is held once: the same content is kept, decoded and embedded once, and a file is read once per document. It was read and kept once for each URL.
- With system fonts on Linux, Chinese, Japanese and Korean text is set as Chrome on Linux sets it: in the default families (Liberation Sans for `sans-serif`), with the characters these lack from the Noto Sans CJK of the text's language. Before, all of it was set in Noto Sans CJK, and characters fell back to the variant whose file came first.
- With system fonts, a character that the fonts of the text lack is looked for in the installed families of `sans-serif` (DejaVu Sans, Noto Sans …) before any other installed font, as fontconfig ranks them for Chrome on Linux. Before, the first installed font with the character in the order of the font files was taken, so Arabic and Hebrew text could come out in DejaVu Sans Mono, depending on where the files lie.
- With system fonts, a family the system lacks takes an installed one with the same glyph widths, as Chrome takes it on Linux through fontconfig: Liberation Sans for Arial and Helvetica, Liberation Serif for Times New Roman and Times, Liberation Mono for Courier New and Courier, Carlito for Calibri, Caladea for Cambria. On Linux, form controls (Arial) and `Courier New` were set in the next family of the list or the standard serif font.
- Trigonometry, powers, roots, logarithms and exponentials in CSS math functions, transforms, gradients, color conversion, rounded and squircle corners, blurs, shadows, SVG paths and the gamma of PNGs are computed with the libm crate instead of the system's math library, whose last bits differ between macOS and glibc and between glibc versions. A PDF that used them could differ by a shade or a fraction of a point between platforms; now the same document gives the same bytes on Linux and macOS. On macOS this changes blurred shadows (the weights of the blur) and the size of some radial gradients by one shade or in the last digit of a coordinate; libm's functions are those of glibc for these. A clippy rule keeps the system's functions out of the engine.
- In tables with `border-collapse: collapse`, rows with `-fagus-repeat: at-break` no longer take part in the borders of pages where they do not show: on the table's first page the head row's bottom border meets the first row (it was replaced by the border of the carry-over row below it), on its last page the last row meets the footer. This also holds for a header or footer with `-fagus-repeat: at-break` on the row group and for rows that break across pages.
- Where a table breaks right before its closing footer, which then goes on to the next page alone, the footer's rows with `-fagus-repeat: at-break` show below the rows on the page where it breaks. They were left out there.
- Rows with `-fagus-repeat: at-break` in a header or footer that does not repeat (taller than a quarter of the page, or with `break-inside: auto`) no longer show where the table does not break: such rows came with the other rows of the header at the table's start, or of the footer at its end. They now repeat on their own where the table breaks, where they are short enough to and their row group avoids breaks inside, and otherwise show nowhere.
- Tagged PDF keeps empty table cells as `TD` and `TH` elements, so that every row of a table has the same number of columns, as PDF/UA-1 requires. A table with an empty cell, such as an empty header in its corner, failed veraPDF's checks 7.2-42 and 7.2-43.
- Conic gradients drawn as images (in PDF/A, with more than 96 stops, and in boxes with `filter`) have the same pixels on macOS as on Linux. Their angles came from the system's `atan2f`, which on macOS differs in the last bit for about one pixel in six, so a few pixels came out one shade off and the files differed. The PDFs made on Linux stay the same.
- A font whose `cmap` maps characters to glyphs it does not have (past its number of glyphs, which format 12 allows) no longer aborts the process when text is written in it: those characters count as missing from the font and fall back to other fonts, and a glyph that shaping still yields past the end is drawn as `.notdef`.
- A font whose em square is not between 16 and 16,384 units, as OpenType requires, is rejected as Chrome rejects it: an `@font-face` rule falls back to the next source or font, and `add_font_data` (the worker's `F`) fails. One of 0 units made rendering stop with an internal error.
- Raster images in SVG images (`<image>` with a PNG, GIF or WebP) and the images that filters change are decoded only up to 200 megapixels, the limit of other images; larger ones are left out. A PNG of a few hundred bytes whose header claimed billions of pixels was decoded into a buffer of hundreds of gigabytes, which aborts the process where the system refuses that much memory.
- An SVG image with a no-break space (or other white space beyond XML's) between the attributes of a tag no longer makes rendering stop with an internal error.
- SVG documents within limits: SVGZ inflates to at most 128 MiB, internal XML entities may add at most 16 MiB of text and hold no markup, and a filter has at most 64 primitives; an SVG past them is not drawn. A few kilobytes of SVG could expand to gigabytes of text through entities of entities, or of data through a gzip bomb, and a filter of a thousand `feFlood` kept a thousand images of its region in memory.
- A WOFF font whose tables declare more than 64 MiB unpacked is rejected before it is unpacked; only the size in its header was checked, which a font of a few hundred kilobytes could understate to unpack to gigabytes.
- A resource URL that percent-encodes an absolute path, a drive or a network share (`%5C%5Chost%5Cshare%5Clogo.png`) is refused before the file system is asked about it. On Windows, such a URL made the engine look at a network share before it found the file outside the root.
- `fagus worker` reads a frame as its data arrives instead of reserving the length the frame claims first: a frame that claimed up to 1 GiB and ended early took that much memory.
- `revert` and `revert-layer` work on custom properties: `--x: revert-layer` takes the value the cascade layers below give, as for other properties. It was taken as the text `revert-layer`, which made a registered property (`@property`) fall back to its initial value.
- Registered custom properties of numbers, percentages, lengths, angles and times are interpolated between two keyframes of an animation, as Chrome prints them: `@property --x { syntax: '<length>' }` halfway from `50px` to `150px` is `100px` in every `var(--x)`. They flipped at the middle before.
- `all` no longer resets `direction` and `unicode-bidi`, which CSS Cascade 4 leaves out of it: right-to-left text with `unicode-bidi: bidi-override` and `all: initial` after it showed left to right.
- `counter(page)` and `counter(pages)` in `string-set` give the number of the page the element is on and the page count, on every page that shows the string: `string-set: chapter content() ' (p. ' counter(page) ')'` printed 0 before.
- An element with `display: none` sets its named strings where its box would be, at the start of the next box (CSS GCPM 3), as do elements with `display: contents` and line breaks; their strings were lost.

## [0.1.0] - 2026-11-16

The first release: a native engine that turns HTML and CSS into PDF the way Chrome prints them, with a PHP package and a Laravel integration on top. Releases before 1.0 may still change the API.

### Added

#### PHP and Laravel

- One Composer package, `nforst/fagus`, for PHP 8.3 and newer. It is a Composer plugin that installs the `fagus` binary of its release for the platform after `composer install` and `composer update`, checked against the SHA-256 the package lists. Binaries exist for Linux (x64 and arm64, glibc 2.17 or newer and musl), macOS (x64 and arm64) and Windows x64.
- An immutable document builder (`Fagus::html()`, `Fagus::xhtml()`) with a worker process that stays warm between documents, resources handed over as bytes or found through a resolver, PDF/A, PDF/UA, Factur-X, attachments, metadata and diagnostics with the position of what was ignored or missing.
- Laravel 13: `Fagus::view()` for Blade views, PDFs as inline or download responses and on filesystem disks, configuration through `config/fagus.php` and environment variables, registered by package discovery.
- Documentation in `docs/`: getting started, the PHP API, Laravel, resources, deployment (Docker, Alpine, servers without access to GitHub, binaries of your own), troubleshooting, a CSS reference, paged media, fonts, PDF output, the command line, the Rust API and the worker protocol.

#### Command line and Rust

- The `fagus` command line tool: `fagus render input.html -o output.pdf` with font directories, a root directory for files, PDF/A and PDF/UA, attachments, Factur-X, `--created` for byte-identical output, `--system-fonts`, `--locale` and `--timings`.
- `fagus worker`, which renders documents for another program over standard input and output and asks it for resources (the protocol is in `docs/protocol.md`).
- The Rust crates of the engine (`fagus` with `Engine`, and the crates below it), used as a git dependency; they are not published on crates.io.

#### Rendering as Chrome prints

- The cascade with origins, layers, `@scope`, nesting, `:has()` and the other selectors of Chrome, custom properties, `@property`, `@container`, `@supports`, `@import`, `revert` and `revert-layer`, presentational attributes of HTML and quirks mode for documents without a doctype.
- Block, inline, float, flex, grid (with subgrid, named areas and lines), table and multi-column layout, positioning with stacking and anchor positioning, intrinsic sizing keywords, `aspect-ratio`, `zoom` and container queries, with many of Blink's details ported, so that documents written with Tailwind, Bootstrap, Bulma and other frameworks print as in Chrome.
- Text: shaping in every script with HarfRust, line breaking and `text-wrap: pretty` and `balance` as in Chrome, hyphenation with the dictionaries of Chrome on Linux (the same on every system), bidirectional text, vertical writing modes, ruby, emphasis marks, `initial-letter`, `text-fit`, OpenType features and variable fonts.
- Fonts: `@font-face` with TTF, OTF, WOFF and WOFF2, `unicode-range`, synthetic bold and italic, and Inter built in, so that Fagus renders without fonts of its own. Installed fonts only when asked for, so that every platform prints the same PDF.
- Painting: colors of CSS Color 4 and 5, gradients in any color space, borders as Blink draws them (including `corner-shape` and `border-image`), shadows, 2D and 3D transforms, filters, masks, `clip-path`, blend modes, and backgrounds sliced across pages.
- Images and graphics: PNG, JPEG, GIF, WebP and SVG (drawn as vectors, inline or as images, with CSS styling, filters and `<foreignObject>`), responsive images, EXIF orientation, MathML Core, form controls, and `<iframe>`, `<object>` and `<embed>` documents.
- Paged media: `@page` sizes, margins and named pages, margin boxes, running elements, named strings, page counters, `target-counter()` and `target-text()`, page breaks inside paragraphs, tables, flex, grid, floats and columns, repeated table headers and footers, and carry-over rows (`-fagus-repeat: at-break`, `docs/extensions.md`).

#### PDF

- Fonts embedded as subsets, vector gradients, links, the document outline from the headings, and compact files with compressed object streams.
- Tagged PDF by default, with the structure of the document in reading order; PDF/UA-1, PDF/A-2b, 2u and 2a, PDF/A-3b, 3u and 3a, attached files, and ZUGFeRD 2 and Factur-X invoices with the XMP metadata they need. `tools/validate.sh` checks the output of the corpus with veraPDF and Mustang.

#### Safety

- No network access and no scripts: resources come only from `data:` URLs, the caller and files inside the document's root directory.
- Limits on nesting, grids, frames, images and the size of substituted values, so that hostile documents render in bounded time and memory, and a panic becomes an error instead of ending the caller. The engine has no `unsafe` code of its own.
